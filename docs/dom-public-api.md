# `dom` public API boundary

This file records the production caller and scope decision for every public
API family in `crates/dom`. Public means an upper crate can name or call it in
a normal build. Implementation types stay crate-private unless a public
cross-crate trait requires otherwise; Stylo's child iterator keeps one
doc-hidden compatibility re-export for its associated type.
An API is retained only when it is either called by production workspace code
or is a complete semantic operation on the generic `Document` boundary. A
diagnostic, cache control, alternate construction path, or partial convenience
operation does not qualify merely because a future adapter might use it.

## Production surface

| API family | Public members | Confirmed production boundary | Why this scope is required |
| --- | --- | --- | --- |
| Core types | `Document`, `Node`, `NodeId` | `bobcat_core::tree::LynxDocument` (= `Document<()>`) is the runtime's document; `flashbulb` accepts documents for capture. | Runtime handles map to document-local ids, while read-only `Node` handles are the document query result. |
| Construction and policy inputs | `Document::new` (takes the permanent document element's tag + payload; `document_element()` returns it non-optionally, `append_document_element` no longer exists), `Device` (dom's own profile struct: `Device::new(width, height, device_pixel_ratio)`, everything else locked — screen, no-quirks, light, coarse touch, fallback font metrics; `standards_device` is the doc-hidden full-parameter test seam), `StylesheetOrigin`, `ElementState`, `Document::{viewport_size,device_pixel_ratio,set_viewport,set_device_pixel_ratio,add_stylesheet}` | `bobcat_core::tree::new_document`, the engine's viewport/device-pixel plumbing, and `flashbulb::frame_size`. | The runtime supplies policy, CSS text, and changing view metrics. Arbitrary device closures, caller-owned base URLs, and detached style resolution are absent. |
| Topology and observable DOM state | `root_node`, `root_element`, `create_element`, `create_text_node`, `append_document_element`, `get`, `is_connected`, `is_ancestor`, `insert_before`, `append_child`, `swap_element`, `remove_element`, `drop_element`, `drop_subtree`; all public `Node` read/navigation methods | Bobcat's native host-module functions use the mutation subset; direct `Document` embedders use the query side. | This is one coherent DOM-subset boundary. Mutation remains document-owned so aligned arenas and invalidation cannot diverge. Removal is split by what it frees, because the embedder owns the payloads: `remove_element` only unlinks, `drop_subtree` frees the whole subtree, and `drop_element` frees exactly one *named* node — an element child is unlinked and stays allocated as a detached root, because an element is what an embedder names (in Bobcat, one script handle each) and it is that owner's to free, while everything under the node that no owner outside the tree could name — its text nodes, its shadow tree in full — is freed with it, or nothing ever would. Internal slot-zero constants, node-kind enums, child-position helpers, and Stylo local-name objects are not exposed. |
| Pre-parsed rule construction | `CssRule`, `CssDeclaration`, `CssKeyframe`, `Document::{build_style_rule,build_keyframes_rule,build_font_face_rule,append_rules}` (author origin only, since the builders resolve names and values in an author parser context) | `bobcat_core::style` lowers a host-decoded `PreparsedStyleSheet` (ultimately a `.web.bundle` `StyleInfo` section) into rules and mounts them. | A `.web.bundle` ships CSS a build step already tokenized, and re-serializing it to a stylesheet blob so it can be re-tokenized is the startup cost `docs/style-assumptions.md` §B.5 rules out. This family is what lets a caller skip the sheet, rule, at-rule, and declaration-block parsers while stylo still owns selector and value parsing. It re-adds, deliberately, the shape PR #68 removed for want of a production caller — with the same containment: `CssRule` is opaque, is mintable only by a `Document`, and `append_rules` rejects a rule minted by another one. The `SharedRwLock`, the `UrlExtraData`, and stylo's own rule types still never appear in a signature. |
| Selector-visible mutation | `set_classes`, `add_class`, `remove_class`, `set_id_attribute`, `set_attribute`, `remove_attribute`, `add_element_state`, `remove_element_state`, `set_text_node_data`, `set_inline_style`, `set_inline_style_property`, `set_inline_style_declarations` | The generic `Document` host boundary; the element layer forwards `set_attribute`, `remove_attribute`, and the `set_classes`/`set_id_attribute`/`set_inline_style` paths `set_attribute` routes into. The native `setInlineStyles` module export is the production caller for `set_inline_style_declarations`, which replaces the whole block from one crossing; `set_inline_style_property` remains the name-based, one-declaration primitive, with no Element-PAPI caller until a numeric-key `__AddInlineStyle` arrives. `add_class`, `remove_class`, and the element-state pair have no Element-PAPI caller yet. | Each method is a complete observable mutation carrying its own snapshot, restyle, and layout invalidation—not a dirty-state control or partial placeholder. The single-property operation follows the name/value subset of CSSOM replacement/removal semantics (no priority argument), serializes the resulting declaration block back to the observable `style` attribute, and exposes no Stylo or Lynx numeric property id. |
| Selector queries | `Document::{query_selector, query_selector_all, matches, closest}`, `InvalidSelector` | The generic `Document` host boundary; the background thread's `lynx.createSelectorQuery()` needs exactly this selector-resolution half underneath its batched `NodesRef` builder (docs/tracking/js-runtime.md). | The four methods are the complete `ParentNode`/`Element` query operations, answered by the same Stylo matcher the cascade uses. `InvalidSelector` is public because each of these APIs is specified to throw a `SyntaxError` `DOMException`, so a parse failure must stay distinguishable from "no match" up to the script boundary; the parsed selector list and matching internals stay private. |
| Custom elements | `CustomElement` (`observed_attributes`, `constructed`, `connected_callback`, `disconnected_callback` (shared `&Document`), `attribute_changed_callback`), `Document::define`; `:defined` now matches | The generic `Document` host boundary; a `customElements.define` binding in `bobcat-core` is the named future consumer, reached through its `tree` module, which owns the built-in Lynx component handlers. No `impl CustomElement` and no definition table may live in `dom`. | Registering one handler per local name and receiving the lifecycle reactions is the complete operation for this scope — user-agent components, where `define` requires every definition to precede its elements and the standard's upgrade half is therefore absent by contract rather than by omission. Reactions are raised by the *existing* mutation methods and invoked before each of them returns, so — exactly as with eager slot assignment — no drain, upgrade, or "resolve pending reactions" call exists to expose. The registry, definition ids, reaction records, the element state machine, and the per-element definition pointer stay private; `:defined` is the only state the machine publishes, and an "is it upgraded" query would be a diagnostic. `disconnected_callback` alone takes a shared `&Document` — it is the one callback that runs with a free already committed, so read-only is what makes re-attaching, re-parenting into, or freeing the doomed subtree unrepresentable instead of merely refused. |
| Shadow trees | `attach_shadow`, `ShadowRootMode`, `shadow_root`, `shadow_host`, `shadow_root_mode`, `assigned_slot`, `assigned_nodes`, `add_shadow_stylesheet`, `Node::is_shadow_root` | The generic `Document` host boundary; the element layer does not yet forward `attachShadow`, and web-core reaches shadow DOM through the same W3C surface (`x-input`'s template, `lynx-view`'s own root). | Attaching a root, reading the assignment it produced, and scoping a stylesheet to it are the complete W3C operations; everything downstream (flat-tree styling, layout, paint, hit testing) follows from them with no second entry point. Slot assignment is recomputed eagerly inside the mutation that changed it, so no "resolve pending assignment" call exists to expose. Flat-tree accessors, the shadow-links struct, `<slot>`/`part` local names, and the scoped `CascadeData` stay private. |
| Event paths | `event::{EventStep, EventSteps}`, `Document::event_steps` | `bobcat-core`'s Lynx main thread builds the path at delivery time, where the document is; the presenting thread crosses only the routed target id. | Working out which nodes an event visits, in which order, and which target each may see is the half that needs the tree, and the only part a caller could not do correctly from outside: shadow retargeting needs the three-tree model. Dispatch is **not** here and cannot be — a listener is a JavaScript value in a realm on another thread — so there is no event object, no listener registry, no sink, and no `preventDefault`; the name, the payload, and the listeners are all above this boundary, and Lynx dispatches no cancelable event in any case. `EventSteps` is plain data carrying no borrow, because it crosses a thread, and it needs no staleness protocol to do so: a `NodeId` names one node for the life of the document, so a step that outlived its node resolves to nothing rather than to whatever took its storage. `PathEntry`, the path scratch, and the walk itself stay private. |
| Layout commit and resources | `layout`, `register_fonts(FontBlob)`, `set_natural_size`, `set_image_source`, `rounded_layout`; `FontBlob`; `layout::{NaturalSize,Size,Layout}` | The native `flushElementTree` module export (= `Document::layout`) is live, and `bobcat-core` reaches font registration from `ViewSources::fonts` while it builds a view. `FontBlob` moves an owned byte container into Parley's retained resource handle without copying its payload; `copy_from_slice` is the explicit fallback for non-owning callers. Natural size and image source are the two intentionally narrow replaced-content seams — both halves arrive from the embedder's `ImageStore` and neither waits for the other; rounded layout is consumed by runtime/product integration tests pending more PAPI. | Only owned font input and device-rounded durable geometry cross the boundary. A borrowed font slice cannot outlive registration without a copy. Unrounded geometry, cache contents, full-cache invalidation, containment views, and text artifacts are implementation state. |
| Input and scrolling | `input` types/constructors plus `route_input`; `scroll` types and document scrolling methods; `Point2D`, `Size2D`, `Vector2D` | the engine's input relay and the macOS Bobcat host; the runtime's input router drives the scrolling methods. | Native/headless hosts normalize positions and every wheel delta to viewport CSS pixels before constructing an event; physical-pixel, line, and page conversion is embedder policy. `route_input` is a pure routing read reporting the node the event hit, which is what lets the layer above decide events and build paths without a second hit test; the crate has no default-action machinery — the user-agent scroll is decided by `bobcat-core`'s input router and executed through `scroll_by`/`scroll_chain`. `InputEvent::with_default_prevented` is the embedder's claim signal to that router; this crate never reads it. Geometry re-exports occur in these signatures. |
| Animation timeline | `Document::{advance_animations,has_active_animations}`, `AnimationTick` | `bobcat-core` calls `advance_animations` on the Lynx main thread — the document's one home — when a `BeginFrame` command carries the presenting side's clock reading. | Stylo owns the animation itself — keyframe resolution, interpolation, and the `Animations`/`Transitions` cascade origins — but not its timeline: the state has to survive a flush, its state machine has to be stepped, and the elements it moved have to be re-cascaded. `advance_animations(now)` is that step, and `now` is a parameter because this crate owns no clock (`crate::input`). It runs wherever the caller holds `&mut Document`, which is what lets the document's owner thread animate on a clock reading the presenting side chose. `AnimationTick` reports only what a frame scheduler needs — whether another frame is owed, how many elements moved, and whether any of them reached layout. The animation map, the per-element sets, the animation-only traversal, and the node bits stay private. |
| Retained visual output | `elements_from_point`, `elements_from_points`, `render`, `commit`, `committed_frame`, `CommittedFrame`, `HitTarget`, `ScrollSlot`, `needs_render`, `scene`, `image_store`, `set_image_store`, `note_images_changed` | Bobcat's private engine composes and hit-tests the published `Arc<CommittedFrame>`; `flashbulb` submits the committed scene; the embedder's `ImageStore` supplies every image the walk draws, and the document retains none. | `render` rebuilds only a dirty frame and is the sole frame producer; `commit` publishes the same retained `Arc`, whose tables answer hit tests and scroll-chain walks with no document and no liveness filter (ids never alias, so liveness is checked where a consumer acts). The document-side `elements_from_point*` queries stay `&self` pure reads of that frame, skipping only items whose node has since been freed. Forced repaint, the paint-order types, and visual epochs are not public; the DOM-free `render` module (GPU backend + the `ImageStore` trait) and the `dom::vello` re-export are the public render floor. |

`Node`'s public methods are read-only observations: identity/kind predicates,
parent/child ids, tag/id/class/attribute/state/text/payload/computed style, and
parent/child/sibling iterators. The iterator implementation types stay hidden;
`children()` returns `impl ExactSizeIterator`.

Rustdoc also shows the methods of the Stylo and `selectors` traits implemented
for `Node`. Those implementations are the required zero-copy engine
integration on the same node type, not a second set of inherent forwarding
methods. Their associated iterator/style-view implementation types have the
minimum visibility Rust permits. Hughie's style view stays crate-private;
Stylo's iterator is doc-hidden at the crate root because the public
`TElement` implementation names it.

## Test and benchmark surface

Normal builds contain none of these entry points:

- `layout-test-utils`: synthetic leaf metrics and explicit per-node layout
  invalidation for Hughie protocol benchmarks.

Internal damage and cache probes use `#[cfg(test)]` and never cross the crate
boundary. Integration tests and benchmarks use production commit paths and
observable state—computed style, rounded layout, scroll offsets, hit targets,
retained scene encoding, or GPU pixels.

## Removed surface

The audit removed four kinds of API that had no production contract:

- alternate CSS internals (`with_url_data`, detached `resolve_style`,
  media-list wrappers, property/font/keyframe inspection, and arbitrary
  device-update closures). The rule builders/appenders were removed here too
  and have since been restored, because pre-parsed `StyleInfo` ingestion is
  the production caller whose absence justified removing them;
- standalone flush status/parallelism and normally visible damage records;
- layout identity/cache plumbing (`mark_replaced`, the natural-size getter,
  unrounded geometry, cache probes, and public invalidation controls);
- forced paint, broad renderer dependency re-exports, slot-zero/node-kind/
  local-name details, and duplicate inline-declaration mutation helpers.

Complete CSS text, document mutations, `layout`, retained-scene scheduling,
and observable query results replace those paths.
