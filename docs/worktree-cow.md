# APFS worktree build caches

The primary checkout's `target` is the seed for independent worktree build
directories. `clonefile(2)` shares their initial data blocks; writes in either
checkout diverge. No sccache, file-content comparison, source changes, shared
writable target, or Git worktree recreation is involved.

## Install and migrate

From the primary checkout, install the shared `post-checkout` hook:

```sh
python3 .github/scripts/worktree-cow.py install
```

The installer copies `.githooks/post-checkout` into the common Git hooks
directory. It refuses an existing unrelated hook or configured `core.hooksPath`
instead of disabling other hooks. Integrate the tracked hook manually in those
cases. Re-run the installer after updating the tracked hook. The installed hook
finds the Python script through the common Git directory, so an old branch does
not need to contain the script. The primary checkout must retain the script.

New `git worktree add` checkouts seed automatically. A normal branch/file
checkout never replaces an existing cache. Neither `--no-checkout` nor a missing
or busy seed blocks Git; an explicit `seed` retries later. Non-macOS automatic
hooks do nothing. Set `BOBCAT_WORKTREE_COW=0` to opt out of an automatic run.

To migrate existing caches, first stop Cargo and rust-analyzer automatic checks
in both the primary checkout and the destinations. Then run either:

```sh
python3 .github/scripts/worktree-cow.py seed --replace /absolute/path/to/worktree
python3 .github/scripts/worktree-cow.py seed --all --replace
```

Batch migration ignores prunable registrations, the primary checkout, already
seeded targets, and worktrees without a target. Each migrated target gets
`.bobcat-cow.json`; repeat migration does not reset subsequent work. To seed a
worktree with no target, omit `--replace`:

```sh
python3 .github/scripts/worktree-cow.py seed /absolute/path/to/worktree
```

After seeding, run the worktree's normal dependency setup and build. For this
repository, install pnpm dependencies and build ReactLynx fixtures before Rust
tests/clippy/benchmarks as described in `AGENTS.md`. The hook deliberately does
not build: Git runs it before submodules or generated JS fixtures may exist.

## Correctness and failure behavior

- Clone into a temporary sibling directory, invalidate the cloned cache, then
  replace `target`. A failed clone leaves the old cache in place. The old cache
  is removed after publishing the new one; no permanent backup holds old blocks.
- Call `clonefile` for every regular file. Unsupported or cross-volume clones
  fail instead of silently making full copies. Preserve symlinks without
  traversing them, and preserve hard-link groups *inside the clone*, with no
  hard links back into the source cache.
- Obtain nonblocking Cargo profile locks while cloning/replacing. These detect
  already-running builds; users must still prevent new builds/profiles from
  starting during migration. A lock on an old directory cannot guard a new
  directory that replaces it.
- Use the primary checkout's offline, locked Cargo metadata to identify
  immutable registry/Git dependencies. Remove local/path and unknown historical
  package fingerprints plus their build-script directories. Leave incremental
  compilation settings unchanged, but omit the seed's accumulated incremental
  directories and compiled examples, plus dependency artifacts whose crate
  names are not recognized as external packages. They must rebuild anyway;
  cloning them can multiply hundreds of thousands of obsolete object files.
  Force Cargo to invoke rustc for local packages even if this branch's source
  timestamps predate the seed's build. Never backdate or touch sources.
- Invalidate external build-script execution fingerprints too: their saved
  outputs can contain absolute paths into the source checkout's `OUT_DIR`.
  Compiled external build scripts and other reusable artifacts remain available.
- Use the conventional repository `target` layout only. Custom target/build
  directories are outside this script's scope. Symlinked targets are refused.
- Ordinary hook failures warn and leave checkout successful; explicit migration
  failures return a nonzero status. No source files or Git index are rewritten.

## Space and verification

Cloning retains the baseline's external artifacts and other retained outputs;
it does not clean the baseline. Local incremental data is regenerated by each
worktree's next build. Rebuilt artifacts consume new space, so assess
volume free-space changes after normal builds, not just immediately after
cloning. `du` can count shared blocks repeatedly, and APFS snapshots can delay
physical reclamation. Do not describe the sum of old target sizes as guaranteed
reclaimed capacity.

Run `python3 .github/scripts/test-worktree-cow.py -v` on macOS. The tests use
small real Git worktrees and Cargo builds without network dependencies. They
cover cloning from an old branch, hook selectivity, old-mtime path-dependency
recompilation, write isolation, internal hard links, busy targets, and failure
before replacement.
